# Migrate from Coinbase x402 to Parallel

If you already use the Coinbase x402 middleware, moving your server to Parallel takes a few minutes. Your routes and prices carry over, written in the Parallel format below. Your agents need the Parallel client: Parallel uses its own payment format, so a Coinbase x402 client cannot pay a Parallel route.

## The change

**Before (Coinbase x402, `x402-express`):**

```ts
import { paymentMiddleware } from "x402-express";
import { facilitator } from "@coinbase/x402";

app.use(paymentMiddleware(
  "0x71C7656EC7ab88b098defB751B7401B5f6d8976F",
  { "/api/search": { price: "$0.01", network: "base" } },
  facilitator
));
```

**After (Parallel x402):**

```ts
import { paymentMiddleware } from "@parallel-protocol/x402/express";

app.use(paymentMiddleware({
  facilitator: { url: "https://agents.parallel.best" },
  routes: {
    "/api/search": {
      price: "0.01",
      network: "base",
      payTo: "0x71C7656EC7ab88b098defB751B7401B5f6d8976F"
    }
  }
}));
```

Install `@parallel-protocol/x402` 0.8.2 or later: since 1 October 2026 the facilitator refuses a settle that does not present the token it issued at verify, and versions before 0.8.0 do not send it. Version 0.8.1 adds the URL checks below.

Keep the facilitator's URL in https, as above. Since 0.8.1, the SDK refuses a plain http URL outside `localhost`, `127.0.0.1` and `[::1]` with an `X402ConfigError` when the middleware is created. It calls that address only and never follows a redirect, which fails the call with `FACILITATOR_UNAVAILABLE`.

Three things change in a route:

- `payTo` moves into the route.
- The price is an amount of each accepted token, without the `$` prefix: `"0.01"` asks for 0.01 USDp, 0.01 USDC, or 0.01 sUSDp.
- The route key is a plain path, and it also covers the paths below it: `"/api"` covers `"/api/search"`. Keys with a method, a wildcard, or a parameter, such as `"GET /api/search"`, `"/api/*"`, or `"/api/[id]"`, match no request, and a request that matches no route is served without payment. Write `"/api/search"` or `"/api"` instead.

## What you gain

- **Automatic conversion** when the agent holds one token and you accept another: between USDp and sUSDp on every network, and with USDC on Base and Avalanche, where USDC backs USDp. The facilitator takes no fee. A swap through the Parallelizer pays its mint or burn fee, on the agent's side: you receive at least your price.
- **Three tokens accepted**: USDp, USDC, and sUSDp (yield-bearing: your revenue earns from the moment it settles).

## What stays the same

- Your handler signatures.
- Your wallet address: payments settle to it.
- Gas: the facilitator pays it on Base, HyperEVM, and Avalanche, as the Coinbase facilitator does.

## What changes for your agents

Agents pay Parallel routes with [`@parallel-protocol/x402-fetch`](/agents/x402/agent-quickstart), a drop-in `fetch` replacement. Parallel uses its own payment format, so a Coinbase x402 client cannot pay a Parallel route.

## Comparison

|  | Coinbase x402 | **Parallel x402** |
|---|---|---|
| Conversion between tokens | No | **Automatic, no facilitator fee** |
| Settles to | Your wallet | **Your wallet** |
| Agent client | Coinbase x402 clients | **`@parallel-protocol/x402-fetch`** |

## FAQ

**Do I lose access to USDC payments?** No. USDC is accepted next to USDp and sUSDp.

**Do I need to update my agent clients?** Yes. Agents pay Parallel routes with [`@parallel-protocol/x402-fetch`](/agents/x402/agent-quickstart). A Coinbase x402 client cannot pay them, since Parallel uses its own payment format.

**Can I run both facilitators in parallel?** Yes. Keep the Coinbase middleware on some routes and put the Parallel middleware on others, or on another deployment. An agent pays each route with the client of its facilitator.
